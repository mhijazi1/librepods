- 2026-11-07: AACP wire format lives in pure `pub(crate)` free functions in aacp.rs. The `encode_*` functions return the data packet without the 4-byte header, and `send_*` methods are one-line wrappers around them. The `parse_*` functions take the payload `&packet[4..]` with the opcode at payload[0], return Option and never panic. `receive_packet` calls the parsers before it takes the state lock. The `GOLDEN_*` byte constants and `golden_` tests pin the current bytes. A protocol change (for example #35) must update the constant in the same commit and justify each changed byte. New packet types get an encoder or parser plus golden and truncation tests, not inline byte building in `AACPManager`. (ticket #7, PR #34)
- 2026-11-07: The check command shares `CARGO_TARGET_DIR` (`<root>/.cargo-target`) across worktrees, and cargo's mtime fingerprints can then reuse a stale test binary built from another worktree. If it did not compile, `touch` the changed sources and rerun. (ticket #7 validation)
- 2026-11-07: Handoff decisions live in the pure, synchronous core `handoff.rs`, `Handoff::handle(now, Input) -> Vec<Command>`. It has no tokio, async or AACPManager. Tests feed `Input`s with an injected `now` and assert exact `Command` lists. `handoff_probe::run` (and #9's default-path wiring) only feeds events and executes commands. New handoff behaviour goes into the core and its event-stream tests, never into shell loop locals. `decide_takeover` is the only takeover policy. Non-legacy takes pass `TakeoverInputs::handoff(trigger, RoutingSnapshot, CaseRecovery)`, and the legacy listener passes `handoff: None`. Routing facts are copied by the decision-free `routing_snapshot`/`routing_snapshot_of`. A control session that died without an event is reported as `Input::SessionLost`, which blocks sends and takes without draining the queue, before any dequeued event or REPL command. `Input::Disconnected` (DropSession) follows only once the queue is empty. (ticket #8, PR #37)
- 2026-11-07: The flake advertises only Linux systems, through `systems.url = "github:nix-systems/default-linux"`, and `nix flake check --no-build --all-systems` must keep exiting 0. Don't add Darwin or other systems unless the outputs are made to evaluate there. Re-lock only the `systems` node with `nix flake update systems`. (ticket #28, PR #46)
- 2026-11-07: The `preferred_codec` setting has one parser, `utils::preferred_codec_from_value(Option<&serde_json::Value>)`. Callers that already hold parsed settings (window.rs) call it directly. `parse_preferred_codec(&str)` wraps it for raw JSON, and `load_preferred_codec` reads the file. - 2026-11-07: A take sent from `Handoff::reconnected` sets the core marker `reconnect_take_pending`. While it is set, `Ownership([0])` only updates `owner`: it doesn't pause and doesn't clear `requested_take`, because the queued init reports answer connect_control's "not owning". The marker clears at the take's `[1]` ACK, at the ACK timeout, on `Disconnected` and in `request()`. Non-reconnect takes keep #841 semantics. Telling a genuine `[0]` inside this window apart from a stale one needs a shell queue-boundary signal (#49). #39 (yield on OwnsConnection=0) must respect this marker. (ticket #43, PR #47)
- 2026-11-07: Smart-routing payloads are OPACK and are built only through the aacp.rs writers `opack_write_str`/`opack_write_uint`/`opack_write_true`/`opack_write_dict_header`, the dict builders `media_information_body`/`tipi_body`, and the framing `smart_routing_packet`, which is opcode + reversed MAC + u16 LE (1 + dict) + 0x01 + dict with no padding. Apple's captured audioaccessoryd payloads from #35 are the reference. They are pinned verbatim as `APPLE_*` hex in `golden_apple_*` tests, and every smart-routing encoder must pass the test-only OPACK walker (`opack_framing_all_smart_routing_encoders`). New or changed smart-routing messages (e.g. #44's RoutedToBluetooth / audioRoutingHijackRequest) use these builders, not hand-written tag bytes or lengths. (ticket #35, PR #48; #50 tracks the remaining hand-built encoders)
- 2026-11-07: The window's battery state is updated only through the pure `merge_battery(prev, update)` in ui/window.rs. It merges per component: an entry present in the update always wins, including a `Disconnected` status, an absent component keeps its previous entry, and a new component is appended. A component with no known level is shown through `battery_level_label` as `--`, never as `0%`. Any rule about which source wins (BLE vs. AACP, ignoring `Disconnected`, #52) goes into `merge_battery` and its tests, not into the event arm. (ticket #41, PR #51)
- 2026-11-07: In `Handoff::ownership`, an `Ownership([0])` that acknowledges no pending release while `requested_take` is set (and outside the #43 reconnect window) is a genuine loss. `yield_take` is the single yield path: it pauses only in automatic mode, drops a pending take (`desired=true`), clears `requested_take`, `stop_during_take` and `play_during_release`, and prints `YIELD`. The [0] that acknowledges a release pauses only for `Cause::User`/`Cause::Quit` (upstream #841) or as the deferred pause of a blocked retake, never for `Cause::Playback`/`Cause::Remote`. That keeps every yield to exactly one PauseMedia. Audio re-routing on yield belongs to #40 and goes through new commands, not into `yield_take` side effects in the shell. (ticket #39, PR #54)
- 2026-11-07: The core maps any `TakeoverAction::Skip(_)` on a manual `Input::Take` to the NO_SESSION WAIT line whenever `!self.live()`, before any other skip-reason line. The policy order in `handoff_block` (recovery before session) stays the same: the session check is applied when the reply is mapped for the shell, not in `decide_takeover`. Shells (the probe REPL, #9's default path) must not add their own `live()` checks. (ticket #42, PR #57)
- 2026-11-07: The check command uses a cargo target dir per worktree (`<worktree>/.cargo-target`), not one shared per clone. A shared dir let a freshly checked-out worktree (older mtimes) reuse a stale test binary from another ticket, so the check could pass on the wrong code (seen in #7, #41, #42). Cost: a cold dependency build per ticket. (orchestrator)
- 2026-11-07: MAC address strings are parsed only by the pure `aacp::parse_mac(&str) -> Option<[u8; 6]>`, which accepts exactly six `:`-separated two-digit hex octets in either case and returns them in address order. Don't call `from_str_radix(..).unwrap()` on MAC components anywhere. Smart-routing encoders that take a target MAC return `io::Result<Vec<u8>>`, with `InvalidInput` naming the address. Their `send_*` wrappers stay `self.send_data_packet(&encode_x(..)?)`, so validation happens before any lock or channel send. `le::verify_rpa` returns false on a parse failure. The self MAC written as an OPACK string is deliberately not validated, so the wire format doesn't change. (ticket #36, PR #53)
- 2026-11-07: Every smart-routing encoder in aacp.rs (hijack_request, show_ui, hijack_reversed, media_information*, tipi) builds its dict only through the OPACK writers, with `opack_write_ref(index)` (0xA0 + index, index < 32) for back-references, and frames it with `smart_routing_packet`. No encoder hand-writes lengths, hex tags or padding. `smart_routing_packet` returns `InvalidInput` for a dict that doesn't fit the u16 length field and never panics. The show-UI `reason` value is the lower-case `hijackv2`, kept byte-identical to the old payload. Don't "fix" its case without a capture. (ticket #50, PR #59)
- 2026-11-07: When a release's ACK times out, `tick()` stores the release's cause in the core marker `timed_out_release`. In `ownership()`, after the #43 reconnect early return and with no pending ACK, a `[0]` consumes the marker as that release's late ACK. It follows #39's release-ACK arm: pause only for User/Quit when `requested_take && automatic`, no YIELD, no second reconcile. The marker clears when it is consumed, on any non-`[0]` ownership report, on `disconnected()` and in `request()`. The marker has no age bound yet (#62). Repeated RemoteOwnershipRequest pauses are tracked in #61. (ticket #55, PR #60)
- 2026-11-07: A repeated `RemoteOwnershipRequest` belongs to the same yield as Linux's earlier `Cause::Remote` release. While that release is pending, the core emits nothing (no PauseMedia, no resend), keeps `pending.since` so the ACK timeout isn't restarted, and says `REMOTE requested ownership; release already pending`. If the release timed out (`timed_out_release == Some(Remote)`, nothing pending), the core re-sends it through `request(now, false, Cause::Remote, ..)` with no PauseMedia. Every other case (first request, pending or timed-out User/Playback/Quit release, pending take, `!live()` checked first) keeps the old behaviour. (ticket #61, PR #63)
- 2026-11-07: The default app path picks who answers AirPods ownership with the top-level `switching` key in preferences.json: `handoff` (default) | `legacy` | `off`. It has one parser, `utils::switching_mode_from_value`, and missing, unknown or invalid values give handoff. preferences.json is read tolerantly. Per-device autoConnect goes only through `utils::auto_connect_from_value`/`load_auto_connect`, and nothing deserializes the whole file into a strict typed map. `switching.rs` is the only switching shell. `AirPodsDevice::new` calls only `Switching::start` and `Switching::dispatch_events`. The router gives every AACP event to the switching mode first, on unbounded channels, and then to the device handlers (ear/CA/stem/tray/UI) in their own task. So handlers never hold up the core, and in Legacy mode the moved legacy reactions run in their own task too. The handoff shell executes `Command`s through an exhaustive match with no `_` arm. It leaves Reconnect/AdoptSession/CancelReconnect to the app lifecycle. Its media actions go through `MediaActions` (`ControllerMedia`), which never takes the outer MediaController mutex. New switching behaviour belongs in handoff.rs; new event plumbing belongs in switching.rs, not airpods.rs. (ticket #9, PR #56)
- 2026-11-07: The #55 marker is `timed_out_release: Option<(Cause, Instant)>`. The Instant is the release's send time (`pending.since`), not the time of the timeout. An `Ownership([0])` counts as that release's late ACK only while `now - sent <= LATE_ACK_WINDOW` (10 s = 2 × `ACK_TIMEOUT`, inclusive). A later `[0]` still consumes the marker, but it is handled as a genuine loss through `yield_take`. Expiry is checked lazily in `ownership()` only: `tick()` never clears the marker, and #61's re-send arm doesn't depend on the marker's age. A hardware capture of real late-ACK delays may retune the constant, and nothing else needs to change. (ticket #62, PR #66)
- 2026-11-07: `activate_a2dp_profile` waits at most `A2DP_RECOVERY_BOUND` (15 s; about 12.75 s with today's constants). This does not count the run time of the lookups and of systemctl. The bound is pinned by a compile-time `const _: () = assert!(a2dp_activation_worst_case_wait() <= A2DP_RECOVERY_BOUND)` and the `a2dp_recovery_worst_case_bound` virtual-clock test. Only the initial lookup in activate and `get_audio_device_index` (deactivate) poll the full `CARD_LOOKUP_ATTEMPTS` (#1/#724 renegotiation window). The re-checks inside the enumeration waits go through `MediaController::a2dp_enumeration_check`, which runs `retry_card_lookup_with(CARD_LOOKUP_ATTEMPTS_PER_CHECK, ..)` (1 attempt, no sleep) around the one-shot `find_card_index` scan (#68). The WirePlumber settle delay is `WIREPLUMBER_SETTLE`. A change to any of these constants (or a new wait in the activation path) must update `a2dp_activation_worst_case_wait` and keep the assert green. Tests count sleeps through `retry_card_lookup_with`, which injects the sleep. (ticket #32, PR #67)
- 2026-11-07: The desktop battery export lives in `battery_provider.rs`. The single BlueZ Battery1 value comes only from the pure `export_percentage(&BudLevels)`. Its rules: a component counts only when it is present and not `Disconnected`; a NotCharging bud wins over a Charging one; otherwise the minimum; otherwise the headphone; the case never counts; the value is clamped to 100. The per-component `BudLevels::apply` keeps absent components. All sink side effects go through `BatteryExporter<S: BatterySink>`: it registers lazily once, makes no call for an unchanged value, calls `remove` when nothing is known and on Drop, and is disabled after one `warn!` if registration fails. The real sink, `BluezBatteryProvider`, runs its blocking D-Bus connection on its own thread at `/org/librepods/battery`, and the AACP handler calls it only through `spawn_blocking`. Only AACP battery is exported, not BLE: BLE ads also arrive while the AirPods are connected to another host. `exportBattery` (default true) has one parser, `utils::export_battery_from_value`. New battery rules (e.g. #52's BLE/AACP precedence) extend these functions and their fake-sink tests. (ticket #18, PR #69)
- 2026-11-07: Call detection is the pure `call_detect.rs` (`is_call_stream`, `is_call_profile`, `airpods_card_profile`, `call_active` over `StreamProps`). Its I/O sits behind `stream_monitor::StreamSource`. Every libpulse list query in stream_monitor.rs goes through `ListAccumulator`, so an Error or a missing End is an `Err` snapshot and `CallPoller` keeps the last state. A local call reaches the core only as `Input::LocalCall(bool)`, which is a local fact and survives `Disconnected`. While it is true, `RemoteOwnershipRequest` with `requested_take` is refused after the `!live()` and #61 arms, and playback-stop releases are held. `LocalCall(false)` releases with `Cause::Playback` if playback is still stopped. Every `Announce` during a call is followed by `AdvertiseCall(true)`. Takes are unchanged: `decide_takeover` still blocks on a remote Call, and taking the AirPods for a call is #12. `AUDIO_CATEGORY_CALL = 401` is provisional until a capture is made (#74). Call-related audio streams belong in `StreamProps` and the #10 classification extends `call_detect`/`stream_monitor`, not media_controller.rs. (ticket #11, PR #72)
- 2026-11-08: The in-call otherDeviceAudioCategory is `AUDIO_CATEGORY_CALL = 501` (OPACK `31 f5 01`), from mo's iPhone cellular-call capture. The category scale is now 100 idle, 301 media, 501 call, all captured. This replaces the provisional 401 noted in the #11 entry. The capture is pinned verbatim as `APPLE_MEDIA_INFORMATION_CALL_YES_501` (playingApp `com.apple.ipTelephony.CallAudioService`, the first capture with the OPACK long-string tag `61 26`). A VoIP/FaceTime call is not captured yet. If it shows another category, add a separate constant and capture test; don't overwrite 501. (ticket #74, PR #76)
- 2026-11-08: When another provider wins BlueZ's first-provider race (e.g. PipeWire's bluez5 HFP battery), LibrePods detects it and documents it. It does not try to win the race. `BatterySink::battery_source` reads `org.bluez.Battery1.Source` on the device object. `battery_owner` decides the owner purely: Absent -> Unknown, which is retried; "LibrePods" -> Ours; anything else or no Source -> Foreign. `BatteryExporter` resolves the owner once per exporter, which means once per connection, and logs one line through its injectable `LineSink` (`new` uses `info!`). Reads go through the provider thread (`Command::ReadSource`), queued after any `Set`, with a bounded wait. BlueZ 5.86's gdbus `InvalidArgs` "No such interface/property" replies are mapped by `battery1_read_from_error`. There is no retry or re-registration to win the race and no nix option to disable PipeWire's provider, because that would also drop other HFP headsets' battery. (ticket #70, PR #78)
- 2026-11-08: `Input::ConnectedDevices` announces only for a remote host in `new` (mac != `self.local`) that is not already in the core's `self.hosts`. The event's `old` is ignored (`old: _`), because a report queued before the session snapshot (seed + Auto, `Reconnected` facts) is replayed with a stale `old`. The `automatic && live()` guard and `self.hosts = new` stay. `disconnected()` still clears hosts, so a host that re-joins is announced again. Known limit (#79, needs #49): when several reports queue in that window, the first replay rolls `self.hosts` back to an older list. Don't fix this with shell-side dedup. Fix it with the #49 queue-boundary signal in the core. (ticket #58, PR #77)
- 2026-11-08: Per-component battery merging has one rule, the pure `ui::window::merge_battery_entry(prev: Option<(u8, BatteryStatus)>, update) -> (u8, BatteryStatus)`. A `Disconnected` update never replaces a known non-Disconnected level/status. It is stored only when nothing is known or the known entry is also Disconnected. A Charging/NotCharging update always wins. The window's `merge_battery` (#41) and the tray update in the `AACPEvent::BatteryInfo` arm of devices/airpods.rs both use it, with the tray's prev = `level.zip(status)`. Don't add a second per-component rule. The window shows `--` for a missing or Disconnected entry, through `battery_label`. The desktop export (`BudLevels::apply`, battery_provider.rs) keeps its own rule. The Headphone label (#81) and le.rs's 0xff tray writes (#82) are not covered yet. (ticket #52, PR #80)
- 2026-11-08: The window's connected-device tab text comes only from the pure `ui::window::battery_tab_label(&[BatteryInfo])`. If a Headphone entry exists (any status), the label uses only that; otherwise it shows Left/Right/Case. Every level goes through `battery_label`, so a missing or Disconnected entry is `--`, and the charging marker `\u{1002E6}` comes from `charging_marker`, only for Charging. Don't put inline battery formatting back in the view. Label changes extend this helper and its `battery_tab_label_*` exact-string tests. This closes the #81 gap noted under #52. le.rs's 0xff tray writes (#82) are still open. (ticket #81, PR #85)
- 2026-11-08: `AirPodsDevice::new` returns `Result<Self, bluer::Error>`. Its first fallible step resolves the local adapter (bluer session, default adapter, adapter address), before `AACPManager::new()`/`connect`, any tray update and any `tokio::spawn`. A failure logs one `error!` naming the AirPods MAC with the systemctl/rfkill hints and returns Err with no side effects. Callers in main.rs `match` on it, log at `warn` (the cause is already logged), and skip the `DeviceManagers` insert and the `DeviceConnected` UI message. They never use `?`, so a startup failure doesn't end the app. New fallible setup steps in `new()` should go into that early block or return Err the same way. Don't add `expect`/`unwrap` there. (ticket #71, PR #87)
- 2026-11-08: Silent but uncorked sink inputs (#88): mo chose (c), no guard until there is evidence. Spike #89 (blocked by #10) checks whether real idle apps keep a takeover-worthy, uncorked, silent sink input open past `MIN_STREAM_PLAYBACK`. If none do, close #88 as not planned. If one does, build (a), per-stream peak detection on the sink monitor. (b), an application exclusion list, is rejected because it misses apps nobody listed. (#88, #89)
- 2026-11-08: BLE proximity tray updates in le.rs go only through the pure `ble_tray_entry(prev_level, prev_status, raw) -> (Option<u8>, Option<BatteryStatus>)`. It turns the byte into an update (0xff -> (0, Disconnected); otherwise `raw & 0x7f`, Charging iff bit 7) and calls `merge_battery_entry` with prev = `level.zip(status)`. A Disconnected result is stored as `(None, Some(Disconnected))`, which keeps the tray's "unknown" shape. So a 0xff byte (case lid closed) keeps the last known tray level, as the window and the AACP tray path do. Don't write tray battery fields directly from BLE bytes. The window path keeps its own `raw != 0xff` filter. (ticket #82, PR #86)
- 2026-11-08: AACP battery reaches the tray only through `MyTray::apply_battery(&[BatteryInfo])` (ui/tray.rs), which applies `merge_battery_entry` per component. It reaches the desktop export only through `battery_provider::export_battery(&Mutex<BatteryExporter<S>>, &[BatteryInfo])`, which is poison-tolerant and called inside `spawn_blocking`. Don't inline either one again. State that an AACP report can set before the event channel is attached is recovered by seeding. `AirPodsDevice::new` attaches the channel with `AACPManager::attach_event_channel(tx) -> Vec<BatteryInfo>`, which sets `event_tx` and clones `state.battery_info` under one state-lock guard (#92). The BATTERY_INFO arm also stores and sends under one guard, so each report is either in the seed (it arrived before the attach) or queued (it arrived after), never both, and the seed is never older than a queued event. The pure `battery_seed(Vec)` (empty -> None) is applied through those same functions before `dispatch_events`. Don't take the snapshot in a separate lock again. `set_event_channel` keeps its signature for the other callers (switching.rs, handoff_probe.rs). The attach stays after `send_notification_request` (#58/#79). Other events in that window (ear detection, connected devices) are not seeded. The race is pinned by the multi-thread test `battery_seed_attach_race_splits_reports_exactly`. (ticket #75, PR #91; one-lock attach: ticket #92, PR #94)
- 2026-11-08: Local playback in the handoff path is `mpris || streams`, combined only in `switching::spawn_playback_poller_with`. The core gets no new Input and still sees only `Input::Playback` edges. Whether a stream is worth taking the AirPods for is decided only by the pure `call_detect::is_takeover_worthy` (media roles music/movie/video/game, or no role but an application name; never event/notification/`event.id`, monitors, LibrePods' own, phone/Communication, or capture). Timing is decided only by `stream_monitor::PlaybackTracker`, keyed by sink-input index: a stream must stay worthy and uncorked for `MIN_STREAM_PLAYBACK` (2 s). The tracker's first successful listing is its baseline: streams already playing then count only after a cork/uncork, matching the core's MPRIS baseline. Each sample's `now` is read after the listing returns. Stream sampling runs in its own blocking task (`spawn_stream_playback`, `watch<bool>`), so a stalled sound server freezes only the stream term at its last value (until #73) and never the MPRIS samples.
